# 机器人防御设计（bot/DEFENSE.md）

机器人开放给大家免费用，但写入规则仓库必须可控。下面是所有**已考虑到的防御点**，
实现时逐条落地。

## 1. 身份鉴权（防规则投毒）

- **只信任 Owner 的转发直接写仓库**：校验 `message.from.id == OWNER_ID`。
- **公众用户默认只读**：转发只触发「检测/分类」，**不直接 commit**。要贡献走审核队列（见 §6）。
- 若机器人暴露了 Webhook/API，必须校验 `secret token`，否则任何人都能伪造转发。

## 2. AI 调用防刷（防 token 轰炸）

AI 是兜底不是核心，且必须限流：

| 措施 | 说明 |
|---|---|
| 按用户限流 | 每 `from.id` 每分钟 ≤ N 条、每天 ≤ M 条，超限拒绝 |
| 重复去 AI | 消息内容 hash 命中缓存 → 直接复用，不调 AI |
| 已命中现有规则跳过 | 该消息已被现有规则覆盖 → 不调 AI（只在「新样本」上花 AI） |
| 短/非广告跳过 | 过短、纯图片/ sticker、明显正常文本 → 不调 AI |
| 每日预算封顶 | 全局 AI 调用次数/花费预算，超了降级为**词典-only**或拒绝 |
| 结果缓存 | 同类签名复用 AI 结论，减少重复推理 |
| 廉价模型优先 | 分类用轻量模型，复杂提取才用大模型 |

**谁的 Key**：Owner 用自己的（预算内）；公众用户**自带 Key** 或走零成本词典路径，
绝不让别人烧 Owner 的 token。免费替代：纯词典 + 本地小模型可完全不调付费 API。

## 3. 输入清洗与边界

- 文本超长截断（如 > 2000 字不处理，防大消息卡顿）。
- 只接受文本转发；忽略 sticker / 图片 / 服务消息。
- 归一化：小写、全角→半角、去零宽字符、压扁空白、去 URL/数字/@mention 噪声。
- 重放保护：同一消息 hash 在时间窗内只处理一次。

## 4. 规则生成安全（防 App 端灾难）

- **只用预置安全模板**：命中类别 → 套该类模板正则（人审过，绝不产生灾难性回溯）。
- 远程正则长度上限 256、拒绝嵌套量词 `(a+)+` 之类（App 端 `kAdFilterMaxPatternLength`）。
- `(?i)` 在加载时自动剥除（见 App `regex_engine`）。
- 生成的规则先**沙箱自测**：用原始消息 + 几条正常样本跑一遍，误伤正常样本则丢弃并告警。

## 5. 防误封（白名单 + 人工兜底）

- 每条新 block 规则生成时，自动对比白名单；若与 `allow:` 冲突，降级或加例外。
- 低置信度 / 模糊样本不自动写，进 `pending/` 等 Owner 审阅。
- 误封反馈通道：用户说「这条不该屏蔽」→ 机器人加 `allow:` 例外并 commit。

## 6. 贡献审核（公开但不裸写）

- 公众贡献落 `pending/<fromId>_<hash>.json`（PR 或隔离文件），**不直写 `rules.json`**。
- Owner 审阅后 `build.py` 合并进 `categories.json` → 重新生成 `rules.json`。
- 恶意/垃圾贡献可直接丢弃，且因限流 + 鉴权，无法刷爆历史。

## 7. 审计与可回退

- 每条规则记录：`addedBy`(from.id/owner/bot)、`addedAt`、`sourceMessageHash`、`source`(类/外部)。
- 仓库写操作**只改 `rules.json`/`categories.json`**，不动其他文件（路径白名单）。
- commit 信息带来源，便于回滚单条规则。
- GitHub API 也限流（避免 403）。

## 8. 其他防御（容易漏的）

- **secret chat 不处理**：TDLib 不暴露明文，无法过滤，文档注明限制。
- **官方赞助消息不屏蔽**：属 Telegram ToS 3.3，App 层赞助消息不进普通列表，天然不作用。
- **仓库公开 ≠ 可写**：raw URL 匿名可读，写需要 PAT（仅 Owner/CI 持有）。
- **机器人自身保活**：token 泄露即吊销重发；日志不含消息明文，只存 hash。
- **多订阅源**：App 可同时订阅本仓库 + Nagram，互不干扰（各自 URL）。
